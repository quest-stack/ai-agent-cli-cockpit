# 英語版を別ダウンロードで提供する方針

2026-09-24。0.2.8で翻訳と言語別ビルドを実装。公開は配布物の検証後に行う。

## 配布の形

- 日本語版と英語版を別のインストーラとして提供する。アプリ内に言語切り替えは置かない。
- ソースは共通とし、文言辞書とビルド時の言語指定で分ける。端末・クリップボード・PTYの修正は両版へ反映する。
- 提供する組合せは日本語／English × Windows ARM64／x64の4種類。ダウンロード画面では言語とCPUを明示する。
- 配布ファイル名の例は `CLI-Cockpit-<version>-en-win-x64.exe`。既存日本語版のダウンロードURLを変える場合は移行を用意する。
- 既存のアプリ識別子と設定保存先は維持し、言語版のインストールでセッションや設定を失わない。2つを同時起動する製品にはしない。

## 実装範囲

1. `App.tsx`、ランチャー、サイドバー、ペイン、検索、終了確認、ヘルプ、ツアー、状態名の文言を共通辞書へ移す。ユーザーのセッション名・フォルダー名やCLI出力は翻訳しない。
2. main側のフォルダー選択、通知、確認・エラー文言、rendererのリンク確認とクリップボード通知も対象にする。`index.html`のlangと数・時刻の表記を言語に合わせる。
3. 言語指定を固定したビルドを作る。成果物ディレクトリを言語別に隔離し、直前の言語のファイルを混ぜない。依存の追加は不要な構成にする。
4. NSISインストーラ、README、導入手順、更新案内を英語でも用意する。更新情報は現在 `urls.arm64/x64` のみなので、旧版の互換性を保ちながら言語別の更新先を追加する。英語版から日本語版へ戻る更新を防ぐ。
5. 起動・復元・終了・検索・コピー・画像／複数行貼り付け・ツアー・失敗表示を両言語で確認する。英語UIの文字切れと日本語文言の取り残しを点検する。

## ビルドと更新の実装

- `src/shared/messages.en.ts` を共通辞書とし、`i18n.ts` の型付きキーで参照する。ユーザー入力は置換対象にせず、そのまま保持する。
- rendererはViteの `__COCKPIT_LANGUAGE__` とHTMLの `lang`、mainは同梱package.jsonの `cockpitLanguage` で言語を固定する。環境変数による指定は開発時だけ有効。
- `npm run build:editions` で日英のビルド、`npm run package:editions` で4種類のNSISインストーラを生成する。対象を絞る場合は `-- --language=en --arch=x64` を付ける。
- 生成物は `dist/editions/ja|en`、配布物は `release/0.2.8/ja|en`。同梱範囲を対象言語の生成物だけに限定し、ソースマップを除外する。
- 日本語版の既存ファイル名を維持し、英語版だけ `-en-` を付ける。NSISの表示言語も各版で固定する。
- 更新情報は従来の `urls` を日本語版用に維持し、`editions.en` に英語版の説明とURLを追加する。英語版用URLがない場合、日本語版へ自動的に案内せず手動ダウンロードを表示する。
- 日英READMEとCHANGELOGを用意し、各版のresourcesには該当言語の文書を同梱する。

## リリース判定

- 共通のtypecheck / lint / unit / buildと、言語別のUI検証を通す。
- 各CPU向けインストーラの実機起動と同梱物検査を終えてから公開する。
- 公開用リポジトリへの反映とリリース公開は、翻訳済み画面・配布ファイルを確認できる状態で扱う。
