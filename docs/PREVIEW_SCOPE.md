# Cockpit プレビュー機能：スコープと画面設計

更新日: 2026-10-24

## 状態

- 初期スコープは、HTML／Webページ、Markdown、画像、PDF、動画の5種類とする。
- 目的は、AIへの依頼と生成物の確認を同じ画面で進め、表示のたびにAIへブラウザ起動を頼む手間を減らすこと。
- 対象形式と開閉・切替UIはユーザー合意済み。0.2.14で一般公開済み。0.2.15では生成物の自動表示と新旧比較の判定を修正する。
- リリース番号・実装時期はこの文書では確定しない。

## Electron本体で利用する操作（2026-10-19）

ビルド後に`node scripts/run-preview-trial.mjs`を実行すると、通常のCockpitとは
別の新しい一時プロファイルで試用できる。既存の設定、起動中CLI、認証設定を引き継がない。

1. 新規タブは閉じた状態で始まり、同じ作業タブのCLI出力で最初のlocalhost URLまたは実在する成果物を検出すると自動で開く。作業タブ右上の「プレビュー」でも開閉できる。
2. 「ファイルを選ぶ」からHTML／Markdown／画像／PDF／MP4を選ぶか、「＋」からローカルファイルの絶対パスを指定する。
3. localhostは「URLを指定」からも開く。利用者が明示的に閉じた後は、再読み込み後も自動では開かない。自動表示中は新しく生成・保存されたPDFや画像などの成果物を表示し、手動で選んだ対象や通常の成果物の復元は維持する。
4. 対象タブで切り替え、境界で幅調整、拡大ボタンで広げる。狭幅はAI／プレビューを切り替える。非表示のCLIも実行と入力状態を維持する。
5. HTML／Markdown／画像は保存後に更新する。PDF／MP4は「更新あり」を見て「新しい版を表示」を押す。動画は再生位置を保持し、停止状態で差し替える。
6. HTML／localhost／Markdownは初回表示を比較の基準として自動保存する。修正後は「変更を比較」でページ全体を左右に表示し、それぞれスクロールして下部も確認できる。「基準を保存」で基準を取り直せる。「画像」へ切り替えると従来の表示範囲のピクセル比較を使える。画像／PDFは画像比較を使う。

### CLI出力から成果物を見つける

- `output/report.pdf`、`preview/index.html`等の相対パスを、出力元CLIを起動した作業フォルダー（Cockpitが記録するcwd）で解決し、実在するファイルだけを候補にする。Cockpit自身の作業フォルダーへ代替しない。
- 対応形式はHTML／Markdown／画像／PDF／MP4。`.ts`、`.js`、`.css`等のソースコードは候補にしない。ANSIの色指定、Markdownリンク、引用符付きの空白を含むパスも扱う。
- 自動表示は「生成・作成・保存した」という完了の出力や、単独の成果物リンクとして提示されたファイルに限る。生成途中、実行コマンドの表示、パスが出ただけの既存画像・PDF・資料、読み込みや参照の出力では自動表示しない。「書き出しました」などの日本語や、端末のリンクに含まれる実ファイルの場所も扱う。判定はCLI出力の一般的な表現に基づき、AIの作業内容を完全に理解するものではない。
- 空のプレビューでは実在する生成物を自動で開き、複数ある場合は最後の成果物を表示する。自動表示中は後から生成されたPDF・画像などへ切り替える。対象タブの手動選択・追加・削除後は選択を維持し、明示選択の記録も作業タブごとに残す。旧版で保存された案内文書は削除せず、明示選択の記録がない場合だけ新しい生成物へ移れるようにする。通常の成果物の復元は選択を維持し、残りの候補は「＋」から選べる。明示的に閉じた画面、比較画面、ファイル選択中には割り込まない。
- 画像などのMarkdownリンクは、空白のURLエスケープ（`%20`）や山括弧付きのパス、ホストなしのローカル`file:///`リンクも解決する。元の作業フォルダーの境界は維持し、遠隔ファイルを自動取得しない。
- フォルダーやファイルを特定できないときは「ファイルを選ぶ」へ案内する。CLI内で移動した後のcwdは追跡せず、記録したフォルダーから見つからない場合も手動選択を使う。
- 自動候補は元の作業フォルダー内だけとし、隠しファイル、範囲外へのパスやシンボリックリンクは候補にしない。手動のファイル選択は引き続き利用できる。
- 出力を短時間まとめ、直近の候補に件数上限を置く。プロジェクト全体の走査やファイルの内容検索は行わない。

AGENTS.md・CLAUDE.md・DESIGN.md・README.md（言語別版を含む）・SKILL.md・CURRENT_STATUS.md・HANDOFF文書は、CLIが読んでも成果物の候補や自動表示の対象にしない。ファイル名の大文字・小文字を区別せず、AGENTS.override.md・CLAUDE.local.mdも除外する。「ファイルを選ぶ」などで利用者が指定した場合は開ける。既に保存されたプレビュー対象は削除しない。

Cockpitの端末から「AGENTS.mdを確認して」「Please edit DESIGN.md」など、ファイル名を含む確認・修正・表示の依頼を送信した場合は、その文書を選択して表示する。既存の文書だけを同じ作業フォルダーの範囲で解決し、隠しファイルや範囲外のリンクは許可しない。入力途中・取消済み・「開かないで」などの否定依頼では開かない。閉じているプレビューも、作業中のタブで新たに明示依頼を送れば開ける。

判定は日英の一般的な依頼表現を対象とするローカル処理で、この判定のために外部AIを呼び出したり、入力原文を記録したりしない。スマホなど別の共有サーバークライアントから送った依頼や、履歴・カーソル編集などで入力内容を確定できない場合は自動判定の対象外とし、ファイル選択で開けるようにする。CLI出力に同じ依頼文が表示されただけでは、起動時の除外を解除しない。

### 変更前後を目視で比較する

1. HTML／localhost／Markdownは初回表示後に「基準を自動保存しました」と出る。その後は基準を指定せず修正を始められる。画像／PDFは修正前に「基準を保存」を押す。どの形式でも、任意の状態で「基準を保存」を押せば同じ対象の以前の基準を置き換えられる。
2. AIやエディターで成果物を直す。PDFは「新しい版を表示」で反映してから比較する。
3. 「変更を比較」を押す。左が保存した基準、右が現在の見た目。変化した範囲を色で囲む。
4. HTML／localhost／Markdownでは「ページ全体」が既定。左右の保存ページをそれぞれスクロールでき、変更した要素を囲む。「画像」は表示範囲のピクセル比較で、左右のスクロール連動と原寸表示を使える。閉じるかEscで通常プレビューへ戻る。
5. 保存した版が複数あるときは「左の版」「右の版」で比較対象を選べる。表示するのは版番号と保存時刻だけとし、履歴管理の専用画面やコードのdiffは追加しない。

- 履歴はHTML／localhost／Markdownを対象とし、初回の自動保存・手動の基準保存・変更の比較時点だけを残す。細かな編集ごとには増やさず、対象ごとに最大3世代、アプリ1起動分の比較データ合計で100MiBまで。ページ本体は1版32MiBまでで、容量上限には比較画像も含める。古い版から自動削除し、同じ内容は重複保存しない。最初の基準が消えた場合は保持中の直前版と比べる。PDF／画像の比較は従来の2版のまま。
- 履歴は作業中だけの一時データとし、Gitや顧客共有フォルダー、外部サービスへ保存・送信しない。終了時に削除し、異常終了で残った分は次回起動時に掃除する。対象は所有者の印がある停止済みCockpitの生成ファイルだけで、起動中の別インスタンスや印のない旧キャッシュ・不明なファイルは消さない。
- 履歴の画像はディスクに置き、選んだ2版だけ読み込む。比較を閉じる・表示方法を変える・版を選び直すと、表示用のページを解放する。常時3画面を動かす方式にはしない。
- 保存ページは閲覧・スクロール用。元のJavaScriptを動かさず、リンク移動・別窓・ダウンロード・ネットワーク接続を許可しない。両側でアプリの動作を試す機能ではない。ページ保存に失敗した場合は画像比較へ切り替えたことを明示する。
- 自動保存した基準は、ファイル保存・開発サーバーの再読み込みなしの更新・表示サイズ変更・プレビューの開閉では置き換えない。比較画面も勝手には開かない。直前の編集単位を自動推定する機能ではなく、自動保存または手動保存した基準と現在を比較する。アプリの再読み込み／再起動では基準を新しく保存する。
- ページ全体の強調は本文と主な表示スタイルの変化を要素単位で検出する。段落追加に伴う位置ずれ・折り返し・スクロールバーによる寸法変化だけでは、同じ本文・スタイルの要素を変更扱いにしない。CSSで指定した幅・高さ・位置の変更と、実際に並べ替えた要素は囲み、押し下げられた既存要素は囲まない。SVGの線色・塗り色等も含め、リングの色変更も囲む。上限は5,000要素、片側500箇所。画像URLが同じままの画像差し替えなどは「画像」のピクセル比較で確認する。条文の意味の比較ではない。
- 「基準を保存」「変更を比較」は対象の読み込み・表示後に使える。読み込み中に再読み込みした場合も最新版の表示を待ち、古い応答を新版として保存しない。画像はデコード完了を確認し、読み込めない画像は基準にしない。PDFビューアーの読み込み途中を基準に保存せず、ページ・倍率を確認できない場合は並べる表示のみとし、強調を行わない。
- 整形済み文の空白・改行、日本語の全角スペースなど、表示に意味を持つ空白も比較する。
- 長い段落も本文全体を照合し、後半の変更を見落とさない。SVGは線色・塗り色だけでなく、円の半径や線の形などの図形属性も照合する。
- Webの画像比較では基準の幅・高さへ一時的にそろえ、閉じると利用者が選んでいたサイズへ戻す。PDFは内蔵ビューアーからページ・倍率を確認でき、両方が一致する場合だけ画像を強調する。確認できない場合も並べる表示は利用できる。同じページ・倍率への移動は利用者が行う。
- PDFビューアーの上部操作欄は強調の対象から外す。本文の見た目を確認するためで、保存した画像自体にはページ番号等の操作欄も残す。
- 画像比較では動画やアニメーション、時刻等の動く要素も違いに含まれる。保存ページでも全アプリ状態の再現は保証せず、PDF全ページ・条文の意味の比較には対応しない。
- Word（.docx）中心の契約書利用は追加要望として記録。文言の追加・削除を追う比較とWordの表示は、今回の画像比較とは別の未実装項目とする。

### Web制作のレスポンシブ確認

HTMLまたはlocalhostを開くと、場所の表示の下に「自動／PC／タブレット／スマホ」が出る。

- PCは1440×900、タブレットは768×1024、スマホは390×844 CSS px。実際のレイアウト幅を切り替えるため、CSSのメディアクエリも指定した幅で動く。
- 「幅」「高さ」に240〜3840の整数を入れて「適用」を押すと任意サイズで確認できる。回転ボタンで縦横を入れ替える。
- 固定サイズは縦横が枠内に収まるよう縮小して表示し、表示倍率を併記する。大きな画面もAIペインの隣で全体を確認でき、プレビューの拡大操作で見やすくできる。
- 「自動」で枠に合わせた幅へ戻す。切り替えてもページを再読み込みせず、入力途中の内容を保つ。選んだサイズは対象ごとに覚える。
- 対象はWebの画面サイズ確認。Safari固有の表示、タッチ操作、モバイルUA、実端末の挙動を再現する機能ではない。必要な実機確認は別途行う。
- PDF／画像／動画にはこの切り替えを表示しない。従来の表示操作を使う。

### 共通動作と制約

- 独立／共有接続のCodex、Claude Code、PowerShell／Shellで同じUIを使う。CLI固有の契約・hook・pluginは不要。
- 主な更新検知は、選んだファイルと実際に読み込んだ相対アセットのメタデータを2回照合する方式。ディレクトリー全体の走査やポート総当たりは行わない。
- 閉じている間はファイルの再読込を行わず、再度開いたときに反映する。別の更新で表示対象を奪わない。動画／音声は切替・閉じる操作で停止する。
- ファイルは一時領域に版を固定して表示し、作成元のファイルを開きっぱなしにしない。古い版は2世代を超えたものから削除し、読込み中の版は次の確認時に再試行する。
- HTML／Markdownは10MiB、画像は100MiB、PDF／MP4は512MiBまで。1つの作業タブは20対象まで。
- ローカルHTMLの相対アセットは選んだファイルの親フォルダー内のみ。隠しファイル、範囲外のシンボリックリンク、拡張子が対象外のファイルを読ませない。外部CDN／フォント等は初期実装では読み込まない。
- localhostの通信先は指定したループバックoriginに限定し、外部へのリダイレクト・別窓は許可しない。通常のWebブラウザを使う入口も残す。
- Markdownは見出し／リスト／表／コード／強調と安全な相対画像・リンクを扱う簡易表示。生HTMLとスクリプトは実行しない。SVGは画像として表示する。
- PDFはChromium内蔵ビューアーを専用の永続partitionで利用する。一時partitionで内蔵部品がブロックされることを最小構成で確認したためで、CLI画面の保存領域とは共有しない。
- PDFのタブ切替ではビューアーを保持するが、新しい版へ反映する際のページ・倍率の継承は未対応。PDF／MP4の再生成途中の完全性は、サイズ・更新時刻の安定とヘッダーを確認する方式であり、生成ツールの完了通知ではない。
- 実AIを使わないWindowsソース版で検証する。Mac実機・Windows/Macの配布アプリでの再検証は公開前に必要。

既存のブラウザUI試作は以下に残す。本体の実ファイル読み込みとは異なる。

## 操作できるUI試作（2026-10-19）

`node scripts/preview-prototype.mjs`で起動し、
`http://127.0.0.1:4174/?preview=prototype`をブラウザで開く。
新規作業タブでは閉じているため、右上の「プレビュー」を押す。
空欄のサンプル一覧か「＋」から、5種類の対象を追加して試せる。

- 開閉、対象の追加／重複防止／閉じる操作、対象タブの矢印キー移動、幅調整、拡大／復帰、狭幅のAI／プレビュー切替を実装。
- 作業タブごとの開閉・対象・選択・幅を、試作専用のブラウザ保存領域に保持。アプリの保存schema・IPC・CLI設定には追加しない。
- Claude CodeとCodexの表示は既存デモAPIであり、実AIを起動しない。シェルを含む他のペインも同じ作業タブのプレビューを使う。
- HTML／Markdown／画像は、操作感を確認するための固定React／SVGサンプル。任意HTMLやMarkdownを読み込む表示エンジンはまだ接続していない。
- PDFは生成した2ページの架空サンプルをブラウザ内蔵ビューアーで表示する。Electron配布版でのPDF表示やページ／倍率の継承を保証するものではない。
- MP4はローカルに存在するffmpegで12秒のH.264／AACサンプルを一時生成。導入・ダウンロードは行わず、生成できなければ動画欄で読込失敗を案内する。
- 動画の実再生・シーク・音量・全画面はブラウザの標準操作を使用。対象／作業タブ／AI表示へ切替時とプレビューを閉じたときに一時停止し、戻っても自動再生しない。
- 「更新を試す」は全サンプルの保存を模擬する操作。対象を奪わず、HTML／Markdown／画像は表示を更新、PDF／MP4は「新しい版を表示」で反映。MP4は時刻を保持して停止する。
- 任意ファイル／URLの追加、CLI出力のURL候補検知、実ファイル保存監視、ファイル再生成との共存、権限分離されたElectron表示は未実装。
- 試作はブラウザ専用で、Electronのpreload APIがある環境では有効化しない。通常の起動URLと配布アプリにプレビュー操作は出さない。

試作テストは、サーバーを起動したうえで
`COCKPIT_PREVIEW_URL=http://127.0.0.1:4174/?preview=prototype`を設定し、
`npx playwright test tests/e2e/preview-prototype.spec.ts`を実行する。
環境変数のない通常CIではこのブラウザ専用試験をスキップする。

## 対応範囲

| 種類 | 初期対象 | 基本操作 | 更新方法 |
| --- | --- | --- | --- |
| HTML／Web | ローカルHTML、localhost／ループバックIP上の開発ページ | 表示、ページ内操作、再読込、外部ブラウザで開く | ファイル保存時に再読込。開発ページはサーバー側の自動更新を利用し、手動再読込も用意 |
| Markdown | `.md` | 見出し・リスト・表・コードを整形表示、スクロール | 保存時に自動更新。読んでいる位置を可能な範囲で保持 |
| 画像 | PNG、JPEG、SVG | 全体表示、拡大縮小、元の大きさで表示 | 保存時に自動更新。表示倍率を維持 |
| PDF | `.pdf` | ページ移動、拡大縮小 | 新しい版を検知したら「更新あり」。利用者が反映し、閲覧中のページを勝手に変えない |
| 動画 | MP4を初期対象 | 再生／一時停止、シーク、音量、全画面 | 再生成完了を検知して「更新あり」。利用者が「新しい版を表示」を押して適用 |

MP4はコンテナー名だけで再生可否を決めず、対応コーデックを含む検証が必要。
初期検証用の基準はH.264映像／AAC音声とし、Remotionで生成した短い動画も使う。
Windows／Macの配布アプリで実再生が通るまで、すべてのMP4に対応したとは表記しない。

Officeファイルの直接描画・編集は初期範囲に含めない。Word／PowerPoint等は、
確認用PDFを併せて生成した場合にPDFを表示する。Officeの変換ソフトを自動導入しない。

## 基本配置と切り替え

既存の作業タブ内で、左のCLIペイン群と右のプレビューを並べる。
プレビューをCLIの分割ペインに置き換えず、既存の分割・ペイン移動・入力操作を保つ。

```text
作業タブ: [サイト作成] [資料作成]                  [プレビュー ON]
┌────────────────────────────┬────────────────────────────────┐
│ Claude Code    │ Codex     │ プレビュー        [拡大] [閉じる] │
│                │           │ [サイト] [記事.md] [説明.mp4] [+] │
│ 修正を依頼する  │ 別案を頼む │ 選択したページ／ファイル            │
│                │           │                                │
│                │           │                                │
└────────────────────────────┴────────────────────────────────┘
```

1. 新しい作業タブではプレビューを閉じた状態から始める。作業画面の「プレビュー」で右側を開閉し、境界のドラッグで幅を変える。
2. プレビュー内のファイル名タブを押し、見る対象を切り替える。種類の選択は不要で、対象の拡張子／URLから表示方法を決める。
3. `+`から「ファイルを選ぶ」「URLを指定」を選べる。パス／ファイルのドラッグでも追加できる。
4. 表示対象の名前・種別・更新状態を常に見せる。同じファイル名は作業フォルダーからの相対パスで区別する。
5. 同じ対象をもう一度開くと既存タブを選ぶ。タブが増えた場合は横スクロールと一覧から選べる。
6. 「拡大」で作業領域をプレビューへ広く割り当て、「戻る」で元の分割比率に戻す。

作業タブとプレビュー内タブは役割を分け、プレビュー内タブには常に
「プレビュー」の見出しを付ける。プレビューを閉じてもCLIや開発サーバーは停止しない。

### 開閉と自動表示

- 初回のlocalhost URLまたは実在する成果物で、アクティブな作業タブの空のプレビューを自動表示する。利用者が明示的に閉じた後はURL検知・ファイル更新・CLI切替を理由に開かない。
- 「閉じる」でCLIへ表示領域を戻す。対象タブ・最後の選択・幅は保持し、同じ「プレビュー」ボタンで再び開ける。
- 最後に利用者が選んだ開閉状態を作業タブごとに記憶する。明示的に閉じた後は、再起動や別タブからの復帰でも閉じた状態を保つ。
- 閉じている間はプレビューの描画・再読込を止め、動画と音声も停止する。再表示時に変更の有無を確認し、種類別の更新規則で反映する。
- URL検知やファイル更新をきっかけに、隠れているプレビューへフォーカスを移したり、入力中のCLIからフォーカスを奪ったりしない。

### Claude Code／Codex／PowerShellとの関係

プレビューはCockpit側の共通機能とし、Claude CodeとCodexのどちらから作成した
成果物も同じUIで扱う。CLI固有のhook、plugin、追加契約を前提にしない。
共有サーバー接続のCodexでも、プレビューの開閉やURL／ファイル指定を利用できる設計とする。

PowerShell（MacはShell）にも手動で開く入口を残す。開発サーバーの起動や
ファイル確認に使えるため、CLIの種類だけでプレビューを無効にしない。
最初のURLや成果物の自動表示と、明示的に閉じた後の動作はAIのペインと同じにする。
同じ作業タブ内でPowerShellのペインへ移っても、開いているプレビューを勝手に閉じない。

### 狭い画面

右側を表示するとCLIの操作幅が確保できない場合は、同じ作業タブ内で
「AI」「プレビュー」を切り替える。隠れたCLIは動作を続ける。
切替時にターミナルや入力中の文章を作り直さない。
プレビューの複数対象は一覧から選べるようにし、小さなタブを大量に並べない。

### 作業タブとの対応

- プレビューの対象一覧・選択対象・開閉・幅は作業タブごとに持つ。
- Claude／Codexのどちらのペインを選んでも、同じ作業タブのプレビューを共有する。
- 別の作業タブへ移動したら、その作業タブで最後に見ていた対象を表示する。
- 初期段階は各作業タブで同時に表示するプレビューは1つ。複数プレビューの同時比較は別の拡張とする。

## 対象を見つける操作

同じ作業タブのCLIが出したローカル開発URLと、実在する対応ファイルを候補にする。
表示対象が空で、利用者が明示的に閉じていない場合は、最初の有効な候補を自動表示する。
明示的に閉じている場合は、利用者が再び開いたときに対象候補を確認できるようにする。
対象を選んだ後は、別のURLやファイルが出ても選択を奪わず、追加候補として案内する。
サーバー停止時はその対象に「接続待ち」を表示し、再接続／URL変更を選べるようにする。

ファイルは利用者が選ぶか、同じ作業のCLI出力に現れたパスを候補として提示する。
いったん選んだ対象は監視し、更新のたびに選び直さなくてよい。
PC全体のファイル走査、ポートの総当たり検出、CLIの指示内容をAIへ送る判定は行わない。
初期のWeb対象はローカルの開発ページとし、外部サイト全般を扱うブラウザ機能は別の範囲とする。

## 更新と閲覧の継続

- 更新検知を理由にプレビュー対象のタブを自動で切り替えない。
- ファイルの書込み途中や一時ファイルを表示しない。完成した版の読込みを確認してから更新する。
- Markdown、画像、ローカルHTMLは保存後に自動更新する。
- PDFは更新通知を出して、利用者の操作で新しい版へ切り替える。反映時のページ・倍率の継承可否は表示エンジンの試作で確認する。
- 動画は更新だけで再生をやり直さない。「新しい版を表示」で更新し、再生位置は新しい長さに収まる範囲で保持、一時停止状態にする。
- 別のプレビュー、作業タブ、AI表示へ移ると動画は一時停止する。戻っても自動再生しない。
- 再生成中に元のPDF／動画ファイルが置き換えられても、表示側が書込みを妨げず、現在の版を読み続けられる必要がある。
- タブ切替中のMarkdownの位置、画像の倍率、動画の時刻等は対象ごとに保持する。Webアプリ内のフォーム状態を保つ方式は試作で検証する。

初期画面、読込み中、接続待ち、更新あり、再生成中、ファイル削除、
未対応形式／コーデック、読込み失敗について、再選択／再読込できる状態を設ける。
再起動後に対象を復元できても、CLIや開発サーバーをプレビュー側から勝手に起動しない。

## 実装境界

- 生成HTML／Webページを、Cockpitのpreloadや端末操作APIを持つ画面と分離する。
- `WebContentsView`を候補に、`nodeIntegration: false`、`contextIsolation: true`、sandboxを保つ。
- 既存のIPC送信元検証はURLの接頭辞判定である。プレビューを追加する前に、mainWindowのwebContentsとトップフレームを明示して照合する設計へ見直す。
- プレビューから端末実行、設定読書き、任意ファイル参照、権限の自動付与へ到達させない。
- ファイル選択と監視はmain側が管理し、拡張子・実体パス・選択範囲を検証する。表示側には対象IDを渡す。
- ローカルのHTMLと相対アセットを扱う場合も、プロトコルハンドラーの参照範囲を限定する。Markdownの生HTML、SVGのスクリプトを権限付き画面で実行しない。
- ローカルWeb対象のURLはscheme・ループバックhost・認証情報の有無を検証する。リダイレクト／別窓／外部リンクにも同じ境界を適用する。
- PDF／動画の版を固定する一時キャッシュが必要な場合は、端末内の専用一時領域で管理する。生成物をGitへ追加したり、外部変換サービスへ送信したりしない。
- Windows／Macの両方を対象とする。MP4の再生・シーク、ファイル再生成との共存、PDF表示を配布版で検証する。
- 新しい依存の採用は別途確認する。現在の本体接続では依存を追加せず、プレビュー専用の検証付きIPCと保存ファイルを追加する。既存のworkspace保存schemaとCLI設定は変更しない。

技術的な根拠:

- [Electron: WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)
- [Electron: Security](https://www.electronjs.org/docs/latest/tutorial/security)
- [MDN: Web video codec guide](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Video_codecs)

## 試作で先に確認すること

1. 1440px程度の通常表示で、既存CLIの2ペインとプレビューを切り替えずに扱えること。
2. 幅を狭めた場合にAI／プレビューが切り替わり、入力中の文章とCLI動作が保たれること。
3. プレビュー対象のタブ移動、拡大からの復帰、別の作業タブへの移動で対象が混ざらないこと。
4. HTML／Markdown／画像の更新で別のファイルへ移動せず、ファイル選択を繰り返さなくてよいこと。
5. PDFを読んでいるとき、動画を再生しているときに再生成しても、勝手に差し替えず「更新あり」を表示できること。
6. 動画の停止・時刻保持・シーク・全画面と、隠れた動画の音声停止が動くこと。
7. 生成中の不完全ファイル、削除されたファイル、未対応MP4、停止したサーバーから復旧できること。
8. プレビュー内容からCockpitの端末／ファイルAPIへアクセスできず、操作権限が混ざらないこと。
9. 新しい作業タブでは最初のURL／実在成果物で自動表示し、明示的に閉じた後はURL出力・ファイル更新・再起動で再表示しないこと。
10. 閉じてもCLI動作と入力は維持され、再表示時に対象タブ・幅・更新状態が戻ること。隠れた動画の音声が出ないこと。
11. Claude Code、独立／共有接続のCodexで同じ操作を使え、PowerShell／Shellでも手動で開けること。
