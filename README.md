# CLI Cockpit

CLI Cockpit は、Claude Code CLI と Codex CLI のセッションを1つの
Electronウィンドウで管理する、Windows向けの社内ターミナルアプリです。
テレメトリは行わず、ワークスペース状態はPC内だけに保存します。
通信は「新しい版が出ていないかの確認」だけで、こちらから情報は送りません。

## 対応環境と事前準備

- Windows 11（ARM64 または x64）
- Node.js 22.12.0 以降
- Claude Code CLI（PowerShellで `claude --version` が通ること）
- Codex CLI（PowerShellで `codex --version` が通ること）

配布されるインストーラはCPUアーキテクチャ別です。

- ARM搭載Windows PC: `CLI Cockpit-<version>-win-arm64.exe`
- Intel / AMD搭載Windows PC: `CLI Cockpit-<version>-win-x64.exe`

Windowsの「設定 > システム > バージョン情報 > システムの種類」で確認し、
一致するインストーラを使ってください。

## 新しいPCで使い始める

1. Node.js、Claude Code CLI、Codex CLIをインストールし、上記の
   バージョン確認コマンドがPowerShellで通ることを確認します。
2. PCのアーキテクチャに合うCLI Cockpitインストーラを実行します。
3. CLI Cockpitを開き、「New Session」でフォルダを指定して起動します。
   フォルダはダイアログから選ぶか、パスを直接入力できます。

初回起動時はプロジェクト候補が空です。候補は「よく使うフォルダを一覧に
出しておく」ための補助機能なので、無くてもフォルダを指定すれば起動できます。

一度使ったフォルダは履歴に残り、ピン留めすれば次回から一覧の先頭に出ます。

初回起動時は使い方ツアーが自動で表示されます。閉じたあとでも、タイトルバー右上の
歯車（設定）から「使い方ツアーを見る」でいつでも開き直せます。

## できること

| 機能 | 説明 |
|---|---|
| セッション | フォルダとCLI（claude / codex / powershell）を指定して起動する。1つのセッションが1つのCLIプロセスに対応する |
| タブ | セッションのまとまりをタブで切り替える |
| ペイン分割 | 1つのタブを左右・上下に分割し、複数セッションを同時に表示する。境界のドラッグで比率を変えられる |
| 状態表示 | セッション名の横のランプで状態が分かる（下表参照） |
| 承認依頼の通知 | CLIが承認待ちになるとWindowsの通知で知らせる。タイトルバーのベルでオン・オフを切り替える |
| 画像の貼り付け | スクリーンショットを撮って `Ctrl` + `V` で貼るだけで、CLIがその画像を読む（下記参照） |
| ファイルのドロップ | エクスプローラからファイルをペインへドロップすると、そのパスが入力される |
| 横断検索 | 開いている全ペインの表示内容をまとめて検索する |
| セッション復元 | 終了時のタブ・ペイン構成を保存し、次回起動時に復元する |
| ピン留め・履歴 | よく使うフォルダをピン留めして、次回から一覧の先頭に出す |
| リモート起動 | 受付フォルダに置かれた依頼から、新しいタブでセッションを起動する（既定は無効。下記参照） |

### セッションの状態ランプ

| 色 | 状態 | 意味 |
|---|---|---|
| 青 | 待機（次のタスク） | 入力を受け付けられる。指示を出してよい |
| 黄 | 作業中 | CLIが処理している。待つ |
| 赤 | 承認依頼 | CLIが確認を求めて止まっている。**こちらの操作が必要** |
| グレー | 終了 | セッションが正常に終了した |
| 濃い赤 | 異常終了 | セッションがエラーで落ちた |

赤（承認依頼）になるとWindowsの通知でも知らせます。他のペインで作業していても
気づけるので、通知はオンのまま使うことを勧めます。

## ショートカット

| キー | 動作 |
|---|---|
| `Ctrl` + `Shift` + `T` | 新しいタブ |
| `Ctrl` + `Shift` + `W` | 現在のタブを閉じる |
| `Ctrl` + `Shift` + `D` | ペインを左右に分割 |
| `Ctrl` + `Shift` + `E` | ペインを上下に分割 |
| `Ctrl` + `Shift` + `F` | 全ペインを横断検索 |
| `Ctrl` + `Tab` / `Ctrl` + `Shift` + `Tab` | 次 / 前のタブへ |
| `Alt` + `←` `→` `↑` `↓` | 隣のペインへ移動 |
| `Shift` + `Enter` | CLIへ改行を送る（送信せずに複数行入力する） |
| `Ctrl` + `Shift` + `R` | 画面を描き直す（文字が欠ける・出なくなったとき） |

## リモート起動（既定は無効）

受付フォルダに置かれた依頼から、新しいタブで `claude` を起動する機能です。
外出中に手元のPCへ作業を始めさせておき、Remote Control で続きをスマホや
ブラウザから触る、という使い方を想定しています。

**この機能は既定で無効です。** 使うには設定（歯車）の
「受け取った依頼でセッションを起動する」をオンにしてください。

### 使い方

オンにしたうえで、次の場所にJSONファイルを置きます。

```text
%APPDATA%\claude-cli-cockpit\inbox\<任意の名前>.json
```

```json
{
  "cwd": "C:/work/my-project",
  "title": "案件名",
  "prompt": "テストが落ちている原因を調べておいて"
}
```

`cwd` だけが必須です。`prompt` を書くと、CLIの起動後に最初の指示として
送られます。ファイルは処理された時点で削除されます。

### 安全のために決めていること

| 項目 | 内容 |
|---|---|
| 通信 | ネットワークのポートは開きません。ローカルのファイルを見に行くだけです |
| コマンド | 依頼側では選べません。常に `claude` を起動します |
| 指示文 | 改行やエスケープなどの制御文字を含む依頼は受け付けません |
| 作業フォルダ | 実在するフォルダでなければ起動しません |
| 記録 | 受理・不受理をすべて診断ログに残します |

**このフォルダに書き込める相手には、このPCで作業を実行させる力を渡すことに
なります。** 共用PCなど、書き込める相手を把握できない環境では有効にしないで
ください。

## バージョンの確認と更新

いま使っているバージョンは、タイトルバー右上の「?」ボタン（または `F1`）で
開くヘルプの見出し横に出ています。不具合を報告するときは、この番号を
添えてください。

更新は手動です。配布先のフォルダから最新版のインストーラを実行してください
（上書きインストールで問題ありません）。設定やセッションは引き継がれます。

<!--
  新しい版が出たら画面内で知らせる仕組みは 0.1.8 で実装済みだが、
  取得先が未確定のため現状では通知が出ない（確認は失敗し、診断ログに
  残るだけでアプリの動作には影響しない）。
  取得先を決めて main.ts の UPDATE_MANIFEST_URL を差し替えれば有効になる。
  そのとき、この節に「新しい版が出るとお知らせします」を書き戻すこと。
-->

更新の確認では、バージョン番号が書かれたファイルを1つ読みに行くだけです。
**こちらから情報は一切送りません。** 確認に失敗してもアプリの動作には
影響せず、オフラインでもそのまま使えます。

## 設定の保存先

タブ、セッション、ピン留め、最近使ったフォルダは次へ保存されます。

```text
%APPDATA%\claude-cli-cockpit\session.json
```

## SmartScreenについて

現在のインストーラは**コード署名を行っていません**（未署名）。そのため実行時に
Windows SmartScreenの警告「WindowsによってPCが保護されました」が表示されます。

社内の正規配布元とファイル名を確認できた場合に限り、警告画面の「詳細情報」→
「実行」から進めてください。出所を確認できないファイルは実行しないでください。

ブラウザやGoogle Driveからダウンロードした場合、ファイルに「ブロック」属性が
付いて起動できないことがあります。その場合はファイルを右クリック →「プロパティ」→
下部の「セキュリティ: 許可する」にチェック →「OK」で解除できます。

## 表示が崩れたとき

画面が真っ黒になる、文字が欠ける、枠と中身がずれる。この症状は
**アプリが自動で直すようになりました**（0.1.7〜）。何も操作しなくても、
数分以内に元に戻ります。

一部のPCでは、画面を描く方法を自動で切り替えて崩れを防いでいます。そのPCでは
文字の形や間隔など、見え方がわずかに変わることがありますが、不具合ではありません。

絵文字を含む行だけ表の罫線がずれる症状は 0.1.9 で直しました。絵文字は
他の文字と同じ幅に収まるよう、少しだけ小さく表示されます。

それでも気になるときは `Ctrl` + `Shift` + `R` を押してください。その場で
すぐ描き直します。

| いつ起きるか | 見え方 |
|---|---|
| 操作中（最も多い） | 打った文字が出ない、文字が欠ける |
| しばらく放置したあと | 画面が真っ黒になる（中身は消えていない） |
| ペイン分割・ウィンドウのサイズ変更のあと | 枠と中身の幅が合わず、行が折り返されて崩れる |

自動でも手動でも、やっていることは同じです。文字を描くための内部データを
作り直して全ペインを描き直します。**CLIには何も送りません**。作業中でも、
CLIが処理中でも、会話や実行中の処理には影響しません。

崩れているのは表示だけで、CLIの側は正常に動いています。中身が消えたわけでは
ないので、慌てて閉じる必要はありません。

<!--
  この症状は xterm.js のグリフ描画（WebGL）が、時間経過やレイアウト変更で
  実際の描画条件と噛み合わなくなることに由来する。根本原因は未確定。

  0.1.7 で予防的な自動再描画を入れた（3分ごと・ウィンドウ復帰時）。
  redraw は CLI へ何も送らないため、崩れの有無を判定せず定期実行しても
  副作用がない。これで利用者が回復手段を知らなくても症状が出なくなる。

  Qualcomm Adreno GPU + ANGLE(D3D11) では、複数の WebGL コンテキストを
  作った直後に既存ペインのテクスチャアトラスが壊れる実測例がある。
  WEBGL_debug_renderer_info を起動中に一度だけ読み、該当機では WebglAddon を
  読み込まず DOM renderer を使う。判定不能時は従来どおり WebGL を使い、
  cockpit.forceWebgl="1" で GPU 判定を上書きできる。

  「いつ起きるか」の順序は実測に基づく。診断ログ11日分（手動回復27回）の
  うち26回は直前6秒間に CLI の入出力があり、放置時より操作中の発生が多い。
  0.1.6 までの本文は「放置したあと」を筆頭に挙げていたが実態と逆だった。

  効果測定: python scripts/analyze-redraw.py
  対策前の基準値は 1.26 回/時間（平均47分に1回）。
-->

## スクリーンショットをCLIに渡す

画面を撮って、ペインで `Ctrl` + `V` を押すだけです。

1. `Win` + `Shift` + `S` などで範囲を撮る（クリップボードに入る）
2. ペインをクリックして `Ctrl` + `V`

画像は一時ファイルとして保存され、そのパスが入力欄に入ります。あとは
「この画面のエラーを見て」などと続けて送れば、CLIが画像を読みます。

Windows では CLI へ画像を直接貼れないことが多いため、この経路が要になります。
文字列がクリップボードにある場合は、そのまま文字列として貼り付きます。

## 既知の制限（アルファ版）

- **表示が崩れることがある**（真っ黒になる・文字が欠ける・枠とずれる）。
  0.1.7からアプリが自動で直すが、直るまで最大3分かかる。すぐ直したいときは
  `Ctrl` + `Shift` + `R`。根本原因は未確定で、現状は自動再描画で症状を抑えている
- インストーラは未署名のため、初回実行時にSmartScreenの警告が出る（上記参照）
- 更新は自動では入らない。新しい版が出ると通知するが、インストーラの実行は手動
- Windows専用。macOS / Linux では動作しない
- 日本語入力の変換中表示は、xterm.js側の制約を独自に補正しています。表示の
  乱れを見つけたら、操作手順とあわせて報告してください

## 開発

```powershell
npm install
npm run typecheck
npm run lint
npm run test:unit
npm run build
```

ネイティブモジュールを再構築する必要がある場合は、次を実行します。
`rebuild:native` は実行PCのアーキテクチャを使い、ARM64に固定されていません。

```powershell
npm run rebuild:native
```

## インストーラ作成

```powershell
npm run package:arm64
npm run package:x64
npm run package:all
```

`package:all` はARM64版とx64版をまとめて生成します。成果物は `release/` に
出力され、ファイル名にアーキテクチャが含まれます。

## プロジェクト候補が表示されない場合

候補が無くても起動はできます。ランチャーでフォルダを選ぶか、絶対パスを
直接入力してください。一度使えば履歴に残ります。

候補（`settings.scanRoots`）は `session.json` を直接編集すれば増やせます。
スキャンは登録フォルダの**直下1階層だけ**を対象にするため、案件そのものでは
なく、複数案件を含む1つ上のフォルダを指定します。

```json
"scanRoots": ["C:\\work", "C:\\work\\clients"]
```
